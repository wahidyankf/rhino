# Why the Grouped Schema Is Generated

The grouped v2 configuration has one typed Rust model. Serde reads the
repository document and Schemars generates the checked-in Draft 2020-12 schema.
That makes an editor's structural feedback and Rhino's structural reader share
one source of truth instead of two hand-maintained descriptions that can drift.

The artifact is generated by `cargo xtask schema`; `cargo xtask schema --check`
fails when its bytes no longer match the model. Runtime validation reads local
configuration bytes only. A modeline helps an editor find a schema but never
authorizes Rhino to fetch one.

## Dependency Decision

Schemars is required to derive the published JSON Schema from the Serde model;
the standard library and Serde alone cannot generate that contract. A
hand-written JSON artifact was rejected because it creates a second schema to
maintain. The test-only `jsonschema` dependency validates shared structural
fixtures against Draft 2020-12; it is not linked into the shipped binary.

The selected `schemars` 1.2.2 release provides explicit Draft 2020-12 settings,
and `jsonschema` 0.56.0 validates that draft with its HTTP, file-resolution,
TLS, and IDNA default features disabled. Both are exact-pinned and checked by
the repository's advisory, license, duplicate-source, and registry gates. If
either is abandoned, changes license, or gains an advisory, Rhino owns replacing
or removing it; the generated artifact remains reviewable until a supported
generator takes over.
